# PasteCheck requirements

An app that lives in the macOS menu bar and warns you before you paste when the text or image you copied to the clipboard contains strings that look like sensitive information (API keys, access tokens, private keys, credit card numbers, and so on). The original idea is https://github.com/bannzai/IdeaMemo/issues/358 .

`DIRECTION.md` is the source of truth for the grounds of decisions (hypothesis, decision criteria, decisions made); this document holds only the requirements and invariants. The evaluation report on whether to build it (demand, competition, monetization, feasibility) is recorded in this repository's "build decision" issue (https://github.com/bannzai/pastecheck/issues/1).

## Target users and situations

- Target: developers. People who often paste terminal output, configuration files, or screenshots into AI chats, Slack, GitHub issues, and the like
- Situations: a token from an environment variable was mixed into terminal output or a log copied as a whole. When sharing part of a configuration file, the private key line was selected too. An access key showed up in a screenshot of an error screen
- Current alternatives: check by eye before pasting. Install a free OSS tool with the same function (secretlint/secure-clipboard). Enterprise DLP (which controls pasting into browsers) does not suit individuals

## Invariants

1. **Never let clipboard contents leave the app**: all inspection happens on the device. The clipboard contents (text, images, detected values) are not written to files, logs, `UserDefaults`, or the network. The only exception is passing text to SecChain's matching feature on the same Mac, only for matching. The text is passed via standard input or an XPC message rather than as a command argument (arguments are visible to other processes on the same Mac through `ps`), and only after confirming by signature (Team ID and bundle ID) that the receiver is the genuine SecChain. SecChain's matching feature is built to handle values only in memory and return only the names of matched secrets (a requirement on SecChain. SecChain's existing policy is design decision 8 in https://github.com/bannzai/SecChain/blob/main/documents/PROJECT.md , "The matching is done by `secchain mask`, and the plugin never reads a stored value", meaning matching is done by secchain and no additional process reads values). A warning shows only the detection type, the position (line, column, length), the names of matched SecChain secrets, and the name of the app that was frontmost at the time of detection; it never shows the detected value itself. Matching with SecChain also never keeps SecChain's secret values in PasteCheck's memory, files, logs, or settings. How to apply this when writing code and verifying behavior is in `.claude/rules/clipboard-content-handling.md`
2. **Do not rewrite the clipboard (by default)**: many existing tools replace the value with a mask on copy, but PasteCheck only shows a warning and leaves the decision to paste to the user. It rewrites the clipboard only when the user explicitly presses "Clear clipboard" in the warning. Automatic replacement or blocking of pastes, if ever added, is an opt-in setting
3. **No servers, accounts, or analytics**: no path is created through which the provider receives user information (the privacy policy `docs/privacy.md` is written on this premise)

## Features

MVP scope (the list of "required features" and the judgment of what is in or out are in `DIRECTION.md`):

- Detect clipboard changes and check text against patterns (regular expressions). Target formats: AWS access keys, GitHub tokens (`ghp_` / `github_pat_`), OpenAI (`sk-`), Slack (`xox`), JWT, PEM private keys, credit card numbers (Luhn check), and `.env`-style `KEY=value` (where the value is a long random string)
- When the clipboard text contains the actual value of a secret stored in SecChain (the same author's secret management app, https://github.com/bannzai/SecChain ) (a partial match, for the situation where it is mixed into terminal output copied as a whole), warn regardless of format. The warning shows only the secret's name in SecChain, never its value. The path is to add a matching feature to SecChain, have PasteCheck pass the text, and receive only the matched names (a CLI subcommand or XPC); the idea of PasteCheck reading values by sharing a Keychain access group is not adopted. Which form to use and the changes on the SecChain side are designed in the child issue that implements it
- On detection, notify with a macOS notification (or a small custom window) showing the detection type and position, and the name of the app that was frontmost at the time of detection (`NSWorkspace.shared.frontmostApplication`. It is not necessarily the copy source (when the user switches apps right after copying, or via Universal Clipboard), so the wording makes clear it is "the app that was frontmost", and it is omitted when unavailable). The notification has "Clear" (clears the clipboard by the user's explicit action) and, only for pattern detections, "Not a secret" (counts that warning as a false positive. It is not shown for matches against actual SecChain values, which cannot be false positives)
- When an image is copied, extract its text with Vision OCR and run the same checks
- From the menu bar, pause inspection, turn each detection type on or off, and set launch at login
- On first launch, guide the user through clipboard access permission, notification permission, and SecChain integration. For clipboard access permission, the premise is that macOS asks for confirmation on the first programmatic read (the API is macOS 15.4 and later. The version in which the confirmation appears by default is unverified, as stated in the supported OS row of "Technology stack and infrastructure decisions". Source: https://developer.apple.com/documentation/appkit/nspasteboard/accessbehavior-swift.enum "The default behavior for the General pasteboard is to ask upon programmatic access"); provide guidance to choose allow in that confirmation and guidance for the setting in System Settings > Privacy & Security. The wording and choices of the confirmation dialog (whether "Always Allow" exists) could not be confirmed in Apple's documentation (unverified), so check them on a real machine during implementation and match the wording
- From the menu bar, the user can reach "Contact" (opens a mail addressed to `bannzai.app@gmail.com`) and the privacy policy and terms of use (`docs/`)
- Keep on the device, as per-date counts, the number of warnings shown and the number of times the user recorded a false positive with "Not a secret" in the notification (no content, values, or positions are kept). The menu's "Today's warnings" and the number of useful warnings per period (warnings − false positives) in `DIRECTION.md` "decision criteria" are derived from these per-date counts

Not in the MVP (decide in `DIRECTION.md` "decisions" when adding):

- Intercepting Cmd+V (blocking the paste). Stopping a paste needs an active `CGEventTap` (`.defaultTap`), and WWDC19 "Advances in macOS Security" ( https://developer.apple.com/videos/play/wwdc2019/701/ ) explains that this requires the Accessibility permission. The App Sandbox documentation ( https://developer.apple.com/documentation/security/protecting-user-data-with-app-sandbox ) lists use of the accessibility APIs among its restrictions, and no primary source has been found showing that an active tap works inside the sandbox (Mac App Store distribution) (unverified). A listen-only `.listenOnly` tap needs the Input Monitoring permission and can be used inside the sandbox too (Apple DTS answer https://developer.apple.com/forums/thread/707680 ). If added, it is a Releases-only feature
- Judgment with an on-device language model (Foundation Models). It could judge "text that is sensitive from context" that regular expressions cannot catch, but the supported OS versions and devices are limited
- Automatic rewriting (masking) of the clipboard. Invariant 2
- A Mac App Store version (after the Releases version ships, with only the features that work inside the sandbox)
- Japanese localization (UI text defaults to English)
